# 改进路线与验收条件

v0.11 已实现精准定位、本轮数值核验与短原文字段直送，默认运行上限十步。当前十二个合成模板各重复三次，直送组完整通过 36/36，答案与 Full 全部一致，平均耗时与 P95 均低于 Full。

实现与真实对照见 [当前评测](../results/current/REPORT.md)。三组使用相同十步上限，原插件通过 35/36，直送组 36/36；因此增加上限与减少恢复往返分开比较。仍只有十二个调试模板，下一步优先冻结独立任务检验推广能力。

## 1. 完整事件定位（已实现）

context_find 按指定 JSON 来源、字段名和字符串标识定位对象，返回完整小对象、必要字段及真实 JSON pointer。context_search 对明确事件/id 返回对象与路径，自由文本围绕命中取片段；原方案保留为 lexical 对照。

不能假设事件编号等于数组索引。先根据 event 字段查实际条目位置；出现重复 event 时返回全部候选和冲突状态。自由文本则围绕命中词提取片段，并给出原文偏移。

当前问题不只在 BM25 排序，还在截断与来源范围。先解决 JSON 结构定位；存在实际同义检索需求时再评估向量与词面混合检索，并记录建索引和查询的额外成本。

已经明确证据需求时，eager_evidence 在宿主发送视图中附上短原文字段与归档入口。字段由本轮实际读取提取，保留来源、原文指纹与位置，不用旧历史或评分答案填充；需求不明确时仍允许按需恢复。

当前已声明的 JSON 与文本选择可直送原值，恢复调用从只增加步骤的插件 43 次降到 5 次。未知需求仍可能错误选择恢复工具；按来源的文本查询继续作为补充方案，不能只覆盖冻结模板。

## 2. 限定读取来源与时间语义

当前检索会混合旧读取和本轮新读取。为恢复接口增加宿主可核对的来源筛选：source_ids、业务工具名、文件参数、读取所属任务和观察时间。现在状态优先限定为指定本轮读取返回的来源；历史截至日期查询仍保留对应旧版本。

文件当前读取时间与原文里的业务事件时间应分别保存。缺失时间、同日冲突和相似版本不能靠词面分数决定有效性。

验收：同名文件内容发生变化后，当前任务使用新读取；截至日期任务仍使用历史版本；信息不足时明确未完成或拒答。

## 3. 绑定写入值与本轮原文（已实现首版）

FreshWriteGuard 只接受本轮实际读取返回的原文，按宿主声明的读取参数、字段选择与允许变换重算后再调用写工具。每次核验记录执行来源、原文指纹、实际字段位置、原值、重算值与提交值；无需信任模型自报证明。

首版覆盖数值保持的 Decimal 格式化与整数偏移，选择支持 JSON pointer、唯一 event 和固定 marker 文本记录。409 必须格式化为 409.00，不能自行按分换算；规则不读取评分答案。未知运算与额外业务字段不声称已验证。

测试覆盖错误缩放、旧值、缺失/重复事件、读取失败、缓存/恢复回显与修改前失效；故意错误写入不调用实际 handler，纠正受配置上限约束。当前直送组核验 30 次写入、无拒绝，不能将该组质量提升解释为发生真实拒写纠正。后续评测继续区分规则提示、原文选择、拒绝反馈与最终答案的效果。

## 4. 步骤上限与恢复安排（已调整上限）

固定恢复轮次不能表达“后面还必须写入、检查、输出答案”。结合未完成操作依赖，为恢复保留预算；相同问题不重复搜索，已经定位对象后优先直接读字段。预算不足时返回明确缺失，不猜测或无限回退。

当前上限从六步改为十步，三组同样调整，模型提前完成就停止。实际调用和费用全部计入；直送进一步降低恢复往返，没有自动执行写入或跳过检查。剩余操作的动态预算分配尚未实现。

验收：使用相同的已声明上限，完整任务成功率与 P95 同时满足预设目标；所有被拒绝的请求和失败继续计入成本。工具可否并行以数据依赖为准，不能把有先后关系的读写并行。

## 5. 固定实现的独立评测

增加多文件、不同历史长度、跨时间更新、未知事实、读取报错和实际工具操作。区分已用于调试的任务与冻结的新任务。以独立完整任务为统计单位，多个问题或重复种子不能冒充新的独立样本。

同时设置 Full + 相同核验、仅外置、外置加定位、完整插件等对照，区分收益来源。记录实际压缩子集、首请求与后续缓存分项、全部恢复成本和多次运行差异。

进入更大规模测试前，预先确定允许的准确率差异和验收方法。样本量按成对错误率和目标精度计算；当前十二个复用合成情境只能用于定位问题。

当前优先顺序：**冻结独立评测 → 未知需求的按来源查询 → 扩展时序来源筛选 → 动态剩余操作预算**。相关项目与取舍见 [速度设计](LATENCY_DESIGN.md)，MCP 或其他框架适配放在核心行为稳定之后。
