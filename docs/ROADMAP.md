# 改进路线与验收条件

当前执行检查解决了“漏读仍接受答案”的问题，但完整任务仍为 5/6，低于同样带检查的 Full 6/6。剩余日志任务在实际读取之后反复检索和分页，说明下一轮应优先提高证据到达效率和来源使用正确性。

以下为待实现的设计，不计入已有成绩。

## 1. 完整事件定位

当前 context_search 只返回命中文本块的前 500 字符，目标事件可能位于片段之外。优先为 JSON 对象与数组条目建立结构化索引：返回完整匹配事件、来源 ID 和 JSON pointer，例如 `/events/43/status_code`。

不能假设事件编号等于数组索引。先根据 event 字段查实际条目位置；出现重复 event 时返回全部候选和冲突状态。自由文本则围绕命中词提取片段，并给出原文偏移。

当前问题不只在 BM25 排序，还在截断与来源范围。先解决 JSON 结构定位；存在实际同义检索需求时再评估向量与词面混合检索，并记录建索引和查询的额外成本。

已经明确证据需求时，也可在宿主发送视图中直接附上短原文字段与归档入口，省去额外恢复请求。字段必须由这次实际读取结果提取，保留原文来源，不能用旧历史或评分答案填充；需求不明确时仍允许按需恢复。

验收：在打乱数组、稀疏编号、重复 event、目标位于长对象尾部的任务中获取正确字段；恢复次数和整任务 P95 同时下降，不能只缩短展示片段。

## 2. 限定读取来源与时间语义

当前检索会混合旧读取和本轮新读取。为恢复接口增加宿主可核对的来源筛选：source_ids、业务工具名、文件参数、读取所属任务和观察时间。现在状态优先限定为指定本轮读取返回的来源；历史截至日期查询仍保留对应旧版本。

文件当前读取时间与原文里的业务事件时间应分别保存。缺失时间、同日冲突和相似版本不能靠词面分数决定有效性。

验收：同名文件内容发生变化后，当前任务使用新读取；截至日期任务仍使用历史版本；信息不足时明确未完成或拒答。

## 3. 绑定写入值与本轮原文

执行检查证明 handler 被调用，尚未证明模型使用了这次返回的值。为支持的业务 schema 引入写入证明：执行凭据、返回来源、字段路径和允许的变换。宿主从原文重算后再调用写工具。

先覆盖直接复制、数值偏移、金额格式化，随后扩展。自然语言判断和不支持的计算不能伪装成已验证；核验规则不读取评分答案。

验收：读取新文件后故意提交旧值会被拦截；正确值仍能完成；同时测试操作失败、来源丢失和部分修改。

## 4. 按剩余操作安排恢复

固定恢复轮次不能表达“后面还必须写入、检查、输出答案”。结合未完成操作依赖，为恢复保留预算；相同问题不重复搜索，已经定位对象后优先直接读字段。预算不足时返回明确缺失，不猜测或无限回退。

验收：保持同样六步上限，完整任务成功率提升，恢复循环和 P95 下降；所有被拒绝的请求和失败继续计入成本。工具可否并行以数据依赖为准，不能把有先后关系的读写并行。

## 5. 固定实现的独立评测

增加多文件、不同历史长度、跨时间更新、未知事实、读取报错和实际工具操作。区分已用于调试的任务与冻结的新任务。以独立完整任务为统计单位，多个问题或重复种子不能冒充新的独立样本。

同时设置 Full + 相同核验、仅外置、外置加定位、完整插件等对照，区分收益来源。记录实际压缩子集、首请求与后续缓存分项、全部恢复成本和多次运行差异。

进入更大规模测试前，预先确定允许的准确率差异和验收方法。样本量按成对错误率和目标精度计算；当前六个任务只能用于定位问题。

优先顺序：**完整事件定位 → 本轮来源筛选 → 写入值来源核验 → 剩余操作预算 → 独立评测**。MCP 或其他框架适配放在核心行为稳定之后。
