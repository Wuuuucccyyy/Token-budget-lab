# 实现说明与请求处理流程

本文沿一次问答请求说明项目的输入结构、缓存检查、上下文筛选、回答生成和结果评测。主要实现位于 `token_budget_lab/core.py`、`token_budget_lab/benchmark.py` 与 `token_budget_lab/deepseek.py`。

## 输入与评测标注

每条数据包含 `query`（问题）和 `context`（材料）。`evidence` 与 `expected` 是离线评测标注，仅在推理完成后用于计算指标，算法不会读取这些字段。`fact_id` 用于标记问题对应的事实，只参与错误缓存复用分析。

`data/toy_qa.jsonl` 的首条请求询问图书馆周日是否开放。它与后续问题共享同一段材料，用于区分重复请求、改写请求和对照问题。

## `Pipeline.run` 与缓存作用域

`Pipeline.run` 先根据原始材料、用户命名空间、模型、提示词及压缩配置构造缓存作用域。只要其中一项改变，缓存键也会改变。例如，同一问题所依据的政策由“不开放”更新为“开放”后，不应继续使用旧答案。

`exact` 要求问题字符串完全相同，大小写与标点差异都会影响匹配。`lexical` 将中文字符/双字片段和英文词转换为计数向量，再计算余弦相似度。该方法衡量的是词面相似度，不理解语义；相似表达中的实体、配额或数值差异仍可能造成错误命中。

当前缓存以列表扫描，适合展示作用域与匹配逻辑。数据规模增加后，检索效率、持久化、过期策略和并发控制都需要进一步实现。

## `compress` 与上下文预算

缓存未命中时，`compress` 将材料切分为句子，并调用 `bm25_scores(query, sentences)` 估计相关性。低频词区分能力通常更强，评分同时考虑词频饱和和句子长度。

实现从高分句子开始尝试放入预算，每次都重新计算拼接后的长度，以计入换行符；输出前再恢复句子原始顺序。算法保留完整句子，不会截断半句话，因此小预算下可能返回空上下文。系统指令和问题保持不变，所以将上下文长度减半不等于整个 API 输入 token 减半。

当前选择策略是贪心算法，不保证在预算内找到全局最优证据组合。分句逻辑也不能完整处理缩写、表格和代码。

## 回答生成与 API usage

离线 `extractive_answer` 返回最相关的句子，用于验证数据流和缓存行为，不是生成式问答模型；多句推理题不在其能力范围内。

DeepSeek 路径通过 `answer_fn` 接入真实接口，发送筛选后的上下文并记录回答和服务端 usage。凭证从环境变量读取，不写入结果文件。服务端前缀缓存与本项目的精确答案缓存不同：前者仍然发送 API 请求，后者命中时会跳过生成请求。

## 评分指标与统计口径

- **输入减少**：累计请求流中拟发送的输入单位；应用层缓存命中按零次模型调用计。
- **证据保留**：当前问题标注的必要证据是否完整保留在筛选后的上下文中。
- **答案片段通过**：模型输出是否包含预设答案字符串。该粗粒度指标会受否定、冗余和偶然字符串重合影响。
- **错误复用**：缓存来源与当前问题的 `fact_id` 是否不同。同一 `fact_id` 的错误答案仍可能被该指标漏检。

缓存来源上下文即使包含当前问题的正确证据，也不意味着缓存答案回答了当前问题。因此，宽松的近似匹配可能在证据保留率较高时仍降低答案质量。

## 后续实现方向

一项可验证的改动是在相关句子入选后额外保留相邻句，再严格检查总预算和跨句证据覆盖率。另一项改动是检测数字、否定和条件等高风险差异，限制词面缓存复用。两项改动都可能增加输入 token 或降低缓存命中率，需与当前基线做消融对照，并保留负结果。
