# 技术背景与阅读路线

本项目围绕上下文压缩与回答缓存展开。理解实现所需的基础包括模型 token、检索、缓存作用域和任务评测；这些主题可以从当前 Python 原型出发，再对应到代表性论文与工具。

## 问题范围

模型调用开销至少涉及四个不同环节：减少输入文本、减少请求次数、减少输出长度、复用服务端已计算的前缀。前两项是本项目的当前重点，后两项需要单独测量。Token 是模型分词器处理的单位，不等同于汉字或英文单词；不同模型对同一文本的 token 计数也可能不同。

上下文压缩缩短发给模型的材料，但可能同时删除回答依据。回答缓存则在请求完全相同且作用域有效时跳过模型调用，风险在于问题误匹配、缓存过期或跨用户复用。服务端前缀缓存通常仍然产生 API 请求，计费也应按平台返回的 usage 和规则核算，不能与应用层缓存混为一谈。

## 阅读路线

### 1. BM25 句子检索

[rank_bm25 项目与示例](https://github.com/dorianbrown/rank_bm25)

BM25 根据查询与句子的词项重合程度排序。低频词通常具有更强区分度，评分同时考虑词频饱和与句子长度。本项目采用正值 IDF 形式，与 `rank_bm25` 默认 IDF 处理存在差异，因此不将两者的数值视作逐项等价。

关联实现：`token_budget_lab/core.py` 中的 `bm25_scores` 与 `compress`。验证重点是把相关证据放在材料开头或末尾，比较头部截断与按查询检索的结果，并检查同义表达是否被漏检。

### 2. Selective Context

[EMNLP 2023 论文](https://aclanthology.org/2023.emnlp-main.391/)

Selective Context 以内容的信息量为依据删除冗余文本，与本项目的关键词排序属于不同路线。论文中的 self-information 描述内容相对于语言模型预期的惊讶程度，但信息量高并不必然代表内容对当前问题重要。

对比分析可关注否定词、数量词和日期等关键表达被删除后，文本含义如何变化。

### 3. LongLLMLingua

[ACL 2024 论文](https://aclanthology.org/2024.acl-long.91/) · [代码仓库](https://github.com/microsoft/LLMLingua)

LongLLMLingua 将问题相关性、内容位置与 token 预算共同纳入长上下文压缩。与本项目相同，它考虑当前查询；其模型驱动的压缩流程与本项目的 BM25 句子排序在方法和成本上不同。

复现对比可针对同一材料提出截止日期、材料份数等问题，并检查筛选结果及其输入 token 数。

### 4. LLMLingua-2

[ACL Findings 2024 论文](https://aclanthology.org/2024.findings-acl.57/) · [项目说明](https://github.com/microsoft/LLMLingua)

LLMLingua-2 使用蒸馏数据训练 token 级保留/删除分类器。它代表学习式压缩路线，可与信息量打分和 BM25 检索基线对照。比较时需记录模型依赖、推理成本、目标 token 预算与问答质量。

### 5. Prompt Compression Survey

[NAACL 2025 综述](https://aclanthology.org/2025.naacl-long.368/)

综述提供 prompt compression 方法分类。Hard prompt 通常是可读文本；soft prompt 可以是学习得到的向量表示。阅读时可按训练需求、API 适用性、压缩成本和评测任务整理方法之间的差异。

### 6. LongBench

[官方数据与评测代码](https://github.com/THUDM/LongBench)

LongBench 展示长上下文任务的数据组织、划分和指标。复现实验应明确具体版本与子任务，核验数据许可与获取条件，并记录样本 ID、抽样种子和运行配置。相同问题应由同一个模型分别处理完整输入和压缩输入，以便解释 token 与答案质量的差异。

## 文献与当前实现的对应

当前 BM25 邻域方法通过半径 0/1/2 消融检查局部上下文作用，并不等同于 LongLLMLingua 的模型驱动压缩。LLMLingua-2 已提供可选适配器，但尚无权重实测结果。公开数据采用 SQuAD 文章级改编，固定文章划分；LongBench 仍是后续独立长文本评测来源。

复现主入口为 `scripts/reproduce.py`，实际产物包括材料簇统计、输入与质量图表和失败案例。数据准备、模型协议、实际预算与待执行项目记录在 [实验协议](EXPERIMENTS.md)。

## 阶段性复现安排

| 阶段 | 工作内容 | 产出 |
|---|---|---|
| 1–2 | 运行离线基线，阅读 `CounterBackend`、`sentences` 与 `terms` | 检索分词与模型 tokenizer 的区别说明 |
| 3–4 | 检查 `bm25_scores`、`compress`，构造句子排序样例 | 句子得分与保留结果记录 |
| 5–6 | 分析缓存作用域，测试数字、否定与上下文变更 | 近似缓存错误案例 |
| 7 | 对比不同保留比例及离线指标 | 节省与质量的配置对照 |
| 8–9 | 调用 DeepSeek 小样本及完整请求集 | API usage 与答案人工检查记录 |
| 10–11 | 扩展材料并按文档划分数据集 | 数据来源、许可和划分说明 |
| 12 | 阅读 LongLLMLingua 或 LLMLingua-2 方法部分 | 方法对照笔记 |
| 13 | 实现相邻证据保留或高风险问题缓存限制 | 有无改动的消融结果 |
| 14 | 汇总图表、失败案例与实验局限 | 技术报告初稿 |

## 方法比较维度

1. 优化目标是输入 token、请求次数、输出 token，还是模型计算开销？
2. 方法如何决定删除文本或复用答案？
3. 是否需要训练、额外模型、GPU 或付费调用？
4. 使用什么任务和指标评估压缩后的回答质量？
5. 哪些输入会导致失败，能否构造并复现对应案例？

这些维度用于界定方法适用范围，并将文献中的动机转化为可检验的实验假设。
