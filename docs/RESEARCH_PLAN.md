# 研究问题与实验计划

## 研究目标

本项目考察文档问答中的两类调用开销优化：对完全重复请求复用已有答案，以及按问题筛选上下文。当前原型实现 BM25 句子选择、精确缓存与词面近似缓存，并在离线合成数据和 DeepSeek API 上进行对照测量。

核心问题是：在回答质量变化可接受的条件下，怎样联合选择上下文预算与缓存策略？实验不预设节省 token 必然带来更高效率，也不将现有结果视为算法创新或对既有系统的复现。

## 当前实验

评测集包含 74 条请求、20 份虚构材料和 38 个事实标签，其中 18 条是完全重复请求。DeepSeek 实验在 50% 字符预算下比较完整上下文、头部截断、BM25，以及精确缓存组合。回答片段通过率是自动筛查指标，不足以替代语义评测。

排除精确重复后，56 个非重复问题中，BM25 将输入从 6,339 token 降至 4,495 token，减少 29.1%；预设答案片段通过率从 87.5% 降至 78.6%。按 20 份材料做聚类 bootstrap 后，BM25 相对完整上下文的宏平均通过率差为 -11.7 个百分点，95% 区间为 [-26.7, 0.0] 个百分点。该区间反映当前合成材料集合的抽样波动，不能外推为真实任务的总体区间。

把精确重复缓存收益计入全部请求时，BM25 + exact 的 API 调用从 74 次降至 56 次，prompt token 从 8,391 降至 4,495（减少 46.4%）。这项总收益同时包含检索和重复请求缓存，不能解释为 BM25 单独节省 46.4%。完整设置和局限记录在 [DeepSeek 扩展实验报告](../results/DEEPSEEK_EXPANDED_REPORT.md)。

## 后续实验设计

- 引入来源、许可和版本明确的公开基准，并按文档隔离开发集、验证集和测试集。
- 在验证集选择压缩预算与缓存阈值；固定测试集后不再据其调参。
- 固定模型 ID、提示词、数据版本和运行设置，记录 API 返回的模型名、usage、时延与失败状态。
- 比较完整输入、头部截断、BM25 和 LLMLingua-2；分别比较无缓存、精确缓存和 embedding 语义缓存，并控制输入预算。
- 分开测量冷启动、缓存命中和不同重复请求比例，报告检索与缓存各自的增益。
- 报告 EM/F1 或经标注规范约束的人工评分，分析数字、否定、条件、时效、跨句推理和无答案问题。
- 多随机种子重复运行，随机化策略顺序，并记录模型采样、服务端缓存和网络波动等影响因素。
- 统计压缩、检索、缓存、生成的总耗时与费用；费用按实验日期对应的平台单价计算。

## 结果表述边界

- 当前评测数据是人工构造的虚构材料，不能代表自然流量或真实政策问答。
- 离线基线以字符数计量；DeepSeek 实验报告 API 返回的 prompt token。两者不能互换。
- 不能把全部证据保留率写成回答准确率，也不能把字符串片段通过率等同于语义正确率。
- 当前实验未在相同条件下复现 GPTCache 或 LLMLingua，因此不据此声称优于这些方法。

## 项目概述

本项目实现一个面向文档问答的上下文筛选与回答缓存实验框架，包含 BM25 句子选择、缓存隔离、DeepSeek usage 采集和对照评测。初步结果显示，BM25 能减少输入 token，但在当前合成数据上的答案片段通过率也有所下降；后续工作重点是引入外部基准、提高质量评测可信度并分离缓存和压缩的效果。
