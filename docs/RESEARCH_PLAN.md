# 研究问题与实验计划

## 研究目标

本项目考察文档问答中的两类调用开销优化：对完全重复请求复用已有答案，以及按问题筛选上下文。当前原型实现 BM25 句子选择、精确缓存与词面近似缓存，并在离线合成数据和 DeepSeek API 上进行对照测量。

核心问题是：以任务准确率为首要约束，怎样联合选择上下文预算与缓存策略，再降低 token 消耗和端到端延迟？默认不接受主质量指标下降；若任务允许误差范围，应在验证阶段预先定义。实验首先报告任务质量，再报告 token 与速度，不将节省开销作为弥补回答错误的分数。

当前 BM25 真实实验存在片段通过率下降，因此暂不能作为质量达标的方案。后续必须用实际生成模型、任务对应的评分及人工复核确认质量；在达到质量要求的配置之间比较完整输入/输出成本、P50/P95 延迟，并分别观察缓存命中与未命中。

## 当前实验

评测集包含 74 条请求、20 份虚构材料和 38 个事实标签，其中 18 条是完全重复请求。DeepSeek 实验在 50% 字符预算下比较完整上下文、头部截断、BM25，以及精确缓存组合。回答片段通过率是自动筛查指标，不足以替代语义评测。

排除精确重复后，56 个非重复问题中，BM25 将输入从 6,339 token 降至 4,495 token，减少 29.1%；预设答案片段通过率从 87.5% 降至 78.6%。按 20 份材料做聚类 bootstrap 后，BM25 相对完整上下文的宏平均通过率差为 -11.7 个百分点，95% 区间为 [-26.7, 0.0] 个百分点。该区间反映当前合成材料集合的抽样波动，不能外推为真实任务的总体区间。

把精确重复缓存收益计入全部请求时，BM25 + exact 的 API 调用从 74 次降至 56 次，prompt token 从 8,391 降至 4,495（减少 46.4%）。这项总收益同时包含检索和重复请求缓存，不能解释为 BM25 单独节省 46.4%。完整设置和局限记录在 [DeepSeek 扩展实验报告](../results/DEEPSEEK_EXPANDED_REPORT.md)。

## 公开数据扩展与方法消融

已引入来源与许可明确的 SQuAD 文章级改编：48 篇文章、480 道题，按文章隔离为 280/100/100。100 道测试题的 12 组离线对照已运行，包括三档字符预算与邻域半径消融。50% 预算下，BM25 与半径 1 邻域法的答案片段包含率分别为 72% 和 71%，答案原文保留率为 95% 和 96%；目前没有观察到邻域法对离线回答质量的改善。

配置化入口已记录数据、代码、模型协议和思考设置；公开历史 CSV 的分析脚本也已纳入仓库。整库段落检索与三档自适应证据预算已完成开发/测试各 100 题离线诊断，以及 20 题、100 次 DeepSeek 调用。真实试验相对固定大预算少用输入 token 28.5%，但未表现出相对打乱预算的质量优势，仍存在截断；尚不能认为满足准确率优先要求。给定正确文章的压缩 API 对照和 LLMLingua-2 权重推理尚未执行。详细状态与命令见 [实验协议](EXPERIMENTS.md)。

## 后续实验设计

v0.4 增加短、中、长历史条件和按显式事实、时间范围选择证据的原型。结果分开报告整体任务质量、实际发生压缩的任务质量和累计模型成本；多个长度条件按基础场景聚类。当前试验仍是单次合成诊断，后续需要未参与调试的独立自然轨迹及重复运行。设置见 [长历史协议](LONG_CONTEXT_EVALUATION.md)。

连续工具评测已纳入更新、时序、拒答和实际文件操作，完成四个开发任务的三检查点真实对照。全部回退 Full 的恢复组虽然通过全部检查点，但总 token 增加 20.2%，尚无压缩质量证据。后续需同时报告真正压缩的请求比例和任务完成率，修正字段 `total` 与汇总意图的混淆，并在未用于调试的任务上验证。官方 LongMemEval Oracle 子集已接入，生成评审尚未运行。

Python agent 历史中间件已实现原文归档、按问题恢复与完整回退，完成 24 题、100 次 DeepSeek 调用。恢复模式首次历史较短，但计入多次恢复后总 token 仅减少 0.18%，P95 上升；严格评分受格式偏差影响，尚未验证质量等价。下一轮先统一格式要求和消除重复恢复，再固定实现做独立会话与自然工具任务评测，分别检查事实正确性、答案一致性及累计成本。状态和原始结果见 [记忆实验报告](../results/agent_memory/REPORT.md)。

- 在现有文章级公开数据之外接入 LongBench 的固定子任务，扩展多跳、跨文档与无答案任务。
- 在验证集选择压缩预算与缓存阈值；固定测试集后不再据其调参。
- 固定模型 ID、提示词、数据版本和运行设置，记录 API 返回的模型名、usage、时延与失败状态。
- 比较完整输入、头部截断、BM25 和 LLMLingua-2；分别比较无缓存、精确缓存和 embedding 语义缓存，并控制输入预算。
- 分开测量冷启动、缓存命中和不同重复请求比例，报告检索与缓存各自的增益。
- 报告 EM/F1 或经标注规范约束的人工评分，分析数字、否定、条件、时效、跨句推理和无答案问题。
- 多随机种子重复运行，随机化策略顺序，并记录模型采样、服务端缓存和网络波动等影响因素。
- 统计压缩、检索、缓存、生成的总耗时与费用；费用按实验日期对应的平台单价计算。

## 结果表述边界

- 历史 API 数据是人工构造的虚构材料；新增公开数据是 SQuAD 派生任务，两者均不能代表自然请求流量。
- 离线基线以字符数计量；DeepSeek 实验报告 API 返回的 prompt token。两者不能互换。
- 不能把全部证据保留率写成回答准确率，也不能把字符串片段通过率等同于语义正确率。
- 当前实验未在相同条件下复现 GPTCache 或 LLMLingua，因此不据此声称优于这些方法。

## 项目概述

本项目实现文档问答中的上下文筛选与回答缓存实验框架，包含 BM25 及邻域保留、缓存隔离、整库段落检索、自适应证据预算、配置化 DeepSeek 调用、公开数据划分和统计报告。已有实测揭示输入节省、质量与输出可用性之间的关系；打乱预算对照用于检验按问题分配的贡献。后续重点是独立真实生成评测、匹配实际 token 预算，并引入人工盲评与重复运行。
