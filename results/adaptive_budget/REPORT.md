# 证据需求与自适应输入预算：第一轮实验

本轮检验同一检索器下的预算分配。任务质量先于 token 与速度；离线证据诊断不作为回答准确率。

## 方法与对照

资料库包含全部 48 篇文章，建立 2,258 个带原文偏移的段落块；查询不预先限定到标准答案所在文章。块长度上限 1,200 字符，长段落窗口重叠 160 字符，BM25 召回前 24 个候选。按排名装入完整块，重叠比例至少 60% 的块去重，引用标题与分隔符也计入证据预算。

固定预算为 1,800 / 3,600 / 7,200 字符。自适应规则读取问题、首候选的 IDF 加权词项覆盖率和前两名分数差；复杂问句、低覆盖率或分数接近时提高预算，匹配集中时降低预算。阈值在配置中固定，本轮未依据测试结果调参。

打乱预算对照保留每组题目的自适应预算多重集合，以种子 20261012 重新分配到问题，检验分配规则的作用。它匹配名义平均预算，但完整块装入后的字符数和实际 token 不严格相同；单次打乱仍可能受随机种子影响。

本轮关闭应用层回答缓存，不添加语义检索或重排器。开发集和测试集各 100 道题、10 篇文章。两组问题对应的文章互不重叠；所有文章均作为可检索知识库，这是问题划分，不是未知文章外推评估。

答案片段保留检查任一参考字符串是否出现在所选块正文中；字符串出现可能不是回答该题的证据。完整来源段落覆盖通过原始段落哈希与所选块偏移区间的并集检查，较保守，也不等同于最小必要证据。标准答案、正确文章 ID 和来源段落哈希仅用于选取和生成结束后的评分。

开发集上自适应方案的答案片段保留率与大预算相同，但测试集低 1 个百分点。测试集打乱预算的片段保留率也为 95%，因此本轮离线证据不足以证明按问题分配优于同平均预算的随机分配。

## DeepSeek 真实生成试验

开发集按文章轮转取 20 道题，每篇 2 道，共 10 篇。模型请求名 `deepseek-flash`；`anthropic` 协议，配置 thinking=`disabled`，每次输出上限 512，总调用上限 100。每道题内部用固定种子随机排列方法，单次运行。

所有方法采用相同 JSON 短答案提示，要求 answer、citations、abstain。EM/F1 使用 SQuAD 英文归一化；空答、无效 JSON、截断与拒答均纳入质量分母，失败调用的已知 usage 仍计入消耗。引用校验只检查 ID 存在，尚未验证引用内容是否支持答案。

| 方法 | EM | F1 | 不可用响应 | 总输入 token | 输出 token | 输入减少 | 合计减少 | P50 秒 | P95 秒 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 固定小预算 | 60.0% | 70.1% | 1/20 | 10093 | 3467 | 69.2% | 63.3% | 1.189 | 2.090 |
| 固定中预算 | 60.0% | 69.2% | 4/20 | 17384 | 4171 | 47.0% | 41.6% | 1.190 | 2.956 |
| 固定大预算 | 60.0% | 71.7% | 1/20 | 32804 | 4101 | 0.0% | 0.0% | 1.169 | 2.475 |
| 自适应预算 | 65.0% | 76.3% | 1/20 | 23460 | 4446 | 28.5% | 24.4% | 1.343 | 2.764 |

### 质量差与可用性

| 方法 | 配对 EM 差（百分点） | 文章簇 bootstrap 95% 区间 | 质量筛查 | 响应状态 |
|---|---:|---|---|---|
| 固定小预算 | +0.0 | [-15.0, +15.0] | `incomplete` | `{"ok": 16, "truncated": 1, "abstain": 3}` |
| 固定中预算 | +0.0 | [-15.0, +15.0] | `incomplete` | `{"ok": 16, "truncated": 4}` |
| 固定大预算 | +0.0 | [+0.0, +0.0] | `incomplete` | `{"ok": 18, "abstain": 1, "truncated": 1}` |
| 自适应预算 | +5.0 | [+0.0, +15.0] | `incomplete` | `{"ok": 18, "truncated": 1, "abstain": 1}` |
| 打乱自适应预算 | +10.0 | [+0.0, +25.0] | `incomplete` | `{"ok": 18, "truncated": 2}` |

自适应相对打乱预算的配对 EM 差为 -5.0 个百分点，文章簇 bootstrap 95% 区间 [-15.0, +0.0]。本轮未观察到预算分配规则相对打乱对照的优势。

允许质量下降为 0；bootstrap 以文章而非题目为簇。20 题只有 10 个文章簇，单次自动指标与区间不足以证明质量等价，仍需人工语义复核与更多独立问题。不可用响应会使筛查显示 incomplete，表示可用性要求未满足；已得到 usage 的试验消耗仍可完整汇总。

### 输入计量与速度范围

Anthropic 格式的 `input_tokens` 不含缓存读取和缓存写入。本报告的总输入为 `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`；Chat 格式的 `prompt_tokens` 已含缓存命中，不重复加。原始日志保留，公开数值由原始 usage 重算，执行代码哈希与分析代码哈希分别记录。

| 方法 | 缓存读取 token | usage 未知请求 | 本地检索 P50 毫秒 | 预算与装入 P50 毫秒 |
|---|---:|---:|---:|---:|
| 固定小预算 | 2304 | 0 | 0.823 | 0.113 |
| 固定中预算 | 7296 | 0 | 0.887 | 0.148 |
| 固定大预算 | 15997 | 0 | 0.865 | 0.213 |
| 自适应预算 | 11008 | 0 | 0.838 | 0.255 |
| 打乱自适应预算 | 15355 | 0 | 0.855 | 0.184 |

服务商前缀缓存不可控，会影响账单与速度；输入 token 数量减少不等于同百分比费用下降。端到端计时包含检索、预算分配、证据装入、网络调用及响应解析，排除建索引、计划预计算、日志 fsync 与参考答案评分。未测首 token 延迟、流式响应、并发吞吐量或冷启动总耗时。单轮 P50/P95 不作为稳定速度优势的证明。

字段口径依据 [Anthropic 缓存计量说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#tracking-cache-performance)，参数依据 [DeepSeek 思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

逐题复核见 [失败与指标差异案例](FAILURE_CASES.md)。

## 本轮判断与后续验证

规则实现了按问题分配预算，并降低了相对固定大预算的平均证据长度。预算信号仍是词面启发式，不能确认模型是否获得充分证据；第一轮不能直接宣称在准确率不下降时节省 token 或稳定提速。后续只在开发集改进规则并冻结参数，再进行独立真实生成评测；可加入证据重排、按分面补齐及多种打乱种子，明确区分检索和预算模块的贡献。

## 复现与文件

离线复现无需 API、第三方包或模型下载：

```bash
python scripts/reproduce_rag_budget.py --output local_results/rag-budget-reproduction
```

真实生成使用本机 `DEEPSEEK_API_KEY`，先查看调用计划：

```bash
python -m token_budget_lab.rag_experiment --config configs/rag_budget_deepseek_pilot.json --output local_results/rag-budget-live --plan
python -m token_budget_lab.rag_experiment --config configs/rag_budget_deepseek_pilot.json --output local_results/rag-budget-live --export results/adaptive_budget/deepseek_pilot
```

付费请求先写入 start 记录再调用。已完成的请求可在配置、数据、代码均未变化时用 `--resume` 跳过；未结算尝试或 API 错误阻止自动重试。修改代码后应使用新输出目录。现有付费日志的离线重算不产生 API 调用：

```bash
python scripts/reproduce_rag_budget.py --output local_results/rag-budget-reanalysis --pilot-run local_results/rag-budget-live --publish results/adaptive_budget
```

`dev/`、`test/`、`deepseek_pilot/` 分别提供 manifest、summary 和逐题数值 CSV。原始模型输出保存在被 Git 忽略的 local_results 中。文章与题目来自 [SQuAD v1.1 的本项目划分](../../data/PUBLIC_DATA.md)，并非官方 SQuAD 排名。本轮从整库检索，旧实验给定正确文档，两者任务条件不同，不能把百分比直接比较。
