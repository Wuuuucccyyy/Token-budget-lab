# Agent 历史压缩与恢复实验

本报告保留 v0.2 的设置与结果，对应 [实验源代码版本](https://github.com/Wuuuucccyyy/Token-budget-lab/tree/a199d76628e86c1415706cdb13034270e8e6e6ac)。新增原生基线、JSON 输出和连续工具试验另见 [后续报告](../agent_tools/REPORT.md)，不用于改写本轮评分。

## 结论

2026-10-11 的 DeepSeek 小样本试验完成 24 道题、三种模式，共 100 次实际模型调用。压缩加恢复保留了标注来源消息，但恢复过程增加了调用和输出，累计输入输出 token 相对完整历史仅减少 **0.18%**，P95 从 **1.029 秒**增至 **2.620 秒**。当前结果不支持默认启用插件，也不能证明与完整历史近乎无损。

严格 JSON 格式的主评分受到格式不合规影响。原始主结果全部保留；事后裸值诊断另列，不作为通过质量要求的依据。来源消息保留、格式合规、事实正确与答案一致性分别报告。

## 实验设置

| 项目 | 设置 |
|---|---|
| 模型 | `deepseek-flash`，API 返回同名模型 |
| 协议 | 官方 Chat Completions，非流式，关闭思考 |
| 数据 | 原创合成历史；4 个开发会话，每会话 6 题 |
| 题型 | 旧工具事实、用户更正、跨轮求和、未记录字段、否定约束、跨轮比较 |
| 三组 | 完整历史 `full`；只压缩 `compact`；压缩加恢复 `recover` |
| 预算 | 9,000 个序列化消息字符，保留最近两轮与全部用户/系统消息 |
| 调用上限 | 每题每模式最多 3 次；总上限 216 次，实际 100 次 |
| 输出上限 | 每次最多 512 token |
| 顺序 | 会话按种子 20261011 打乱，题型交错，每题方法顺序打乱 |
| 应用层回答缓存 | 关闭；服务商前缀缓存未主动关闭 |
| 主评分 | 最终必须是唯一键 `answer`、字符串值的 JSON；随后对参考答案算 EM/F1 |

三组均提供相同的历史工具 schema，以隔离历史筛选与恢复的差别。`full` 不压缩；`compact` 的恢复工具仅返回禁用说明；`recover` 可检索、恢复整轮或完整回退。因此 Full 是同一参考 agent 中关闭历史筛选的对照，仍带历史工具，并非任意第三方 agent 的原生基线。未来还需加入完全不注册历史工具的对照。

生成器共提供 20 会话、120 题，开发和测试各 10 会话、60 题；本轮真实生成仅使用开发集中的 4 会话。离线诊断使用测试划分的 10 会话。不同会话的数字不同，但题型与措辞复用；120 题不能视作 120 种独立任务。

每个工具快照人为添加 14 行重复无关日志，以检查删除旧工具输出的行为。这会扩大可压缩空间，不代表自然工具流量。标签和 `evidence_positions` 不进入检索器或模型，只在准备历史/生成结束后评分。

## 真实生成主结果

| 模式 | 严格 EM / F1 | 格式合规 | 来源消息保留 | API 调用 | 总输入 token | 输出 token | 总 token | P50 秒 | P95 秒 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Full | 13/24 = 54.2% | 14/24 | 100% | 25 | 77,650 | 177 | 77,827 | 0.826 | 1.029 |
| 只压缩 | 12/24 = 50.0% | 24/24 | 40% | 37 | 30,833 | 800 | 31,633 | 1.096 | 1.793 |
| 压缩加恢复 | 17/24 = 70.8% | 17/24 | 100% | 38 | 76,928 | 758 | 77,686 | 0.818 | 2.620 |

来源消息保留按有标注来源的题计算；未记录字段题没有正确来源消息，不进入该分母。检查对象是完整原始消息，不是答案字符串出现与否。

只压缩的总 token 减少 59.35%，但丢失旧工具事实，质量不满足要求。压缩加恢复的首次发送历史平均从 14,457.5 减至 8,466.2 个字符，减少 41.4%；累计输入 token 仅减少 0.93%，输出增加 581 token，净节省仅 141 token。不能用首次字符减少比例代表整个任务的成本收益。

恢复模式共有 14 次历史工具调用，Full 为 1 次，只压缩为 17 次。首次准备中 12 题采用压缩历史，12 题完整回退：8 题属于汇总/比较，4 题词项检索不确定。原文恢复与回退帮助保留信息，也使节省空间收窄。

主评分下，恢复模式相对 Full 的配对会话宏平均差为 +16.7 个百分点，95% 会话 bootstrap 区间 **[-16.7, +41.7]**。仅有 4 个独立会话，该区间不足以支持无损或稳定改善；`quality_status` 固定为 `pilot_only_not_certified`，不会输出质量通过。

两个输出格式均合规且规范化答案相同的比例为 Full 14/24、只压缩 5/24、恢复 9/24；分母包含全部配对题，所以格式失败会降低这个指标。它既不是纯语义一致性，也不是事实正确率。

## 格式诊断与案例

系统要求 JSON，而若干用户问题要求只返回数字或模块名；这构成了容易引起输出格式偏差的措辞。Full 有 10 个直接裸值输出；恢复有 5 个裸值输出及 2 个带解释的输出。主评分将这些格式不合规结果记为 0，未自动重试、修复或更换评分。

事后诊断仅接受整个输出为合法 JSON 答案或单个裸值，不从解释中挖取数字，也不按参考答案挑选片段：

| 模式 | 解析值精确匹配参考答案 | 解析值不匹配 | 规则无法解析 | 与 Full 值相同 / 可比较数 |
|---|---:|---:|---:|---:|
| Full | 23 | 1 | 0 | 24/24 |
| 只压缩 | 12 | 12 | 0 | 12/24 |
| 压缩加恢复 | 22 | 0 | 2 | 21/22 |

恢复模式有 2 题无法由该规则直接比较；不能删去这两题后宣称全部任务近乎一致。值不精确匹配也不必然表示事实错误：Full 的一题把正确的算式写进了 `answer` 字符串，EM 仍为 0。裸值规则是在观察格式问题后增加的诊断，未经盲评，不替代预设严格评分，也不是新的确认实验。

可复核案例：

- `agent-04-old_tool_fact`：Full 原始输出 `776`，数值等于参考答案，但不符合 JSON 格式。
- `agent-03-user_update`：Full 输出裸值 `203`；恢复模式输出合法 JSON。此类主评分差异首先来自格式。
- `agent-01-cross_turn_sum`：恢复输出解释中的 `125 + 132 = 257`；规则将整段解释标为需复核，不自动提取最后一个数字。
- `agent-04-cross_turn_sum`：恢复输出说明并附带 `{"answer":"323"}`；由于整个文本并非纯 JSON，同样不通过严格格式。
- `agent-08-cross_turn_sum`：Full 输出合法 JSON，但 `answer` 值为包含 `202 + 209 = 411` 的解释文本；精确匹配失败不能解释为算术错误。
- 只压缩在旧工具事实、跨轮求和和比较题上输出 `UNKNOWN`，这些事实原本存在于被删除的工具消息中。保留全部用户请求不能代替保留工具证据。

原始最终回答来自公开的原创合成数据，发布于 [final_answers.csv](deepseek_pilot/final_answers.csv)，便于逐题检查。主数值见 [per_question.csv](deepseek_pilot/per_question.csv)，诊断输出见 [format_diagnostics.json](deepseek_pilot/format_diagnostics.json)。真实用户历史、凭证、完整请求日志和 SQLite 归档不进入仓库。

|---|---:|---:|---:|
| Full | 100% | 14,479.0 | 0 / 0（完整历史 60） |
| 只压缩 | 40% | 1,358.5 | 60 / 0 |

恢复模式 20 题因汇总/比较回退，10 题因检索不确定回退。这里的 100% 只表示这批样例标注的来源消息被保留，不能写成回答准确率或 token 节省。

## 复现与计量

```bash
# 无付费调用：离线来源检查
python -m token_budget_lab.memory_experiment --config configs/agent_memory_offline.json --output local_results/memory-offline

# 无付费调用：重算已公开回答的事后格式诊断
python scripts/analyze_agent_memory.py --answers results/agent_memory/deepseek_pilot/final_answers.csv --output local_results/memory-format

# 仅显示真实实验计划
python -m token_budget_lab.memory_experiment --config configs/agent_memory_deepseek.json --output local_results/memory-live --plan

# 设置本机 DEEPSEEK_API_KEY 后执行；会产生费用
python -m token_budget_lab.memory_experiment --config configs/agent_memory_deepseek.json --output local_results/memory-live --export local_results/memory-live-public
```

必须使用新的输出目录；首版不自动重放或恢复付费请求。每次调用前写 start、响应后写 usage；汇总从全部调用事件计量，包括未产生最终答案的步骤。本轮 100 次响应均取得已知 usage，没有未知用量请求。全部搜索/恢复后的重复输入和输出都进入 token 总量。

端到端时间包含归档追加、索引构建/检索、筛选、模型请求和工具处理；排除评分、日志 fsync 与首次数据库初始化。首次准备未在真实调用前预热。没有测并发吞吐、首 token 时间或冷启动；服务商缓存与网络波动使单轮耗时不能解释为稳定速度优势。token 总量不等于账单费用。

配置、数据与 Python 模块 SHA-256 记录在 [manifest.json](deepseek_pilot/manifest.json)。随机种子控制本地顺序，不保证服务端生成确定性。离线与真实试验模块指纹一致；数据生成脚本与公开 fixture 用回归测试检查一致性。

## 后续改动的判定依据

首先统一用户请求与输出格式要求，减少模型在已有原文时重复搜索和恢复；加入不注册历史工具的原生 Full 对照。然后固定改动，在未用于调试的会话和自然工具任务上重新评测。

语义检索、事实索引和更强重排可作为候选，但应保留完整历史回退，并验证更新、否定、多跳及未记录信息。质量门槛未达到时不能用 token 节省替代结论。当前报告是机制验证和失败分析，不是质量等价或效率达标声明。
