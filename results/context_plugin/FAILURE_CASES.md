# v0.6 失败复核

所有失败保留在 [failure_cases.json](failure_cases.json)，没有重置错误状态或把最终文本中的工具调用标记当作真实执行。

| 分组与任务 | 失败 | 可确认的原因 |
|---|---|---|
| Full，两个 temporal 实例的首检查点 | 最终答案错误，实际配置正确 | 模型完成正确写入及检查后，最终 answer 给出另一数值。文件正确不能替代答案正确 |
| Full + 核验，temporal-00 首检查点 | 格式、操作和文件状态失败 | 模型把推理及 DSML 调用标记写进普通文本，没有通过 function tool_calls 执行写入。来源核验并未被调用；不把这些文本解析成真实操作 |
| 插件，temporal-01 首检查点 | 步骤耗尽 | 已完成正确写入和检查，仍未在六步内返回最终答案；全部调用计入成本 |
| 插件，temporal-00 首检查点 | UNKNOWN、未完成操作 | 检索过程没有让模型完成本题；归档原文存在不保证模型会使用正确证据 |
| 插件，tool_execution-00 首检查点 | context_stalled | 模型顺序翻页三次，仍未读到目标行；恢复预算耗尽后又请求恢复，连续没有进展而终止。应优先定位具体字段，不能只依赖逐页遍历 |
| 插件及插件 + 核验，tool_execution-01 首检查点 | 必需工具未完成 | 找到旧日志中的正确字段，报告及检查正确，但未执行当前问题明确要求的 read_log。历史恢复不能替代用户要求的实际工具调用 |

插件 + 来源核验的 24 个检查点中，答案和文件状态均正确，仍因缺少指定读取操作失败一个。其完整任务通过 7/8，与 Full + 核验的 7/8 相同，但失败发生在不同任务，不能解释为逐题等价。

本轮未观察到插件 + 核验成功写入错误版本；这仅覆盖已声明的配置字段和有限运算合同。没有覆盖任意工具写入、复杂自由表达或自然任务独立样本。
