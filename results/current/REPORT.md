## 核验内容

宿主从当前用户要求声明读取参数、字段选择与允许变换，在实际读取 handler 返回后绑定本轮原文。格式化使用 Decimal，保留数值大小；整数偏移使用明确的常量。提交值不符时先拒绝写入，并反馈真实原文重算值，模型可在原六步上限内纠正。宿主不自动写入。

核验不读取标准答案、目标文件状态或缺失/重复标签。所有条件题仍只声明相同的必需读取；是否唯一由实际文件决定。规则提示仅包含选择与变换，首次请求没有计算出的答案。组间区别同时包含核验提示与拒绝反馈，不能把通过率变化全部归因于某一次拦截。

## 本轮结论与轨迹

Full + 相同核验通过 12/12；不加核验的压缩插件与核验插件均通过 11/12。文件状态正确从 11/12 提高到 12/12，完整任务通过率在这次同轮对照中没有提高。复用任务上的单次差异不能当作一般准确率保证。

同一文本末尾目标中，不加核验组从本轮原文读到 status_code=206，却写入并回答 2.06；核验组提交 206.00，通过原文重算与实际写后检查，但六步耗尽，没有最终答案，因此仍按任务失败计分。

Full 与核验插件各有 10 次写入核验通过，均未触发拒绝。故意提交 409→4.09、204→2.04 的回归测试能验证拦截，但本轮真实成绩不能证明发生了纠错干预；规则提示、生成随机性和拒绝机制需分别评估。

核验插件在文本题先用 context_find 查不存在的 marker JSON 字段，随后多次分页恢复 log_text，耗尽了最终回答所需步骤。下一步优先明确 JSON/文本恢复入口并保留最终回答预算；保持六步上限，不用增加步骤掩盖问题。

插件核验组与 Full 的逐任务答案一致率为 91.7%。单次、复用的合成诊断不足以证明一般任务准确率近乎无损；宿主只验证配置的数值写入，最终答案仍独立评分。

## 完整任务成本与延迟

- 核验插件相对 context_structured：总 token 增加 6.4%，固定参考费用增加 6.1%，P95 为其 1.24 倍。
- 核验插件相对 full：总 token 减少 82.1%，固定参考费用减少 82.8%，P95 为其 1.28 倍。

本轮共 156 次真实请求，未知 usage 0 次，固定参考费用合计 $0.094822。使用命中/未命中分项重算，全部失败、恢复、纠正与最终回答均计入；不是账户账单或实时价格。

真正发生压缩的任务另见 [case_groups.json](case_groups.json)。禁止写入任务中的模型写调用尝试仍记违规，即使宿主核验拦截、未落盘。没有增加步骤、重置状态或重跑至通过。

逐项写入核验从实际 handler 日志重新计算，并核对 canonical 来源 ID、读取参数和原文 SHA-256；不会用结果标签验证来源。既有实验的费用继续保留在调用账本，旧质量成绩不与本轮混合。
