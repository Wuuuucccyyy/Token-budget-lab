## 质量与步骤

步骤上限从六步调整为十步，三组同样增加。只增加步骤的插件与字段直送组分开对照，不把增加预算的效果全部归因于直送。任务提前完成就结束，实际调用数与完整成本仍全部统计。

字段直送组完整任务通过 36/36，三次重复均为 12/12；答案、文件状态与本轮实际读取全部正确，最终答案与 Full 逐项一致。没有步骤耗尽、恢复停滞或禁止写入尝试。

只增加到十步的原插件通过 35/36，文本末尾题在三次重复中均完成最终回答；仍有一次缺失事件任务连续恢复无结果而终止。增加步骤解决了回答机会不足，但没有解决所有检索循环。

Full 答案与文件状态全部正确，完整任务通过 33/36。三次失败是在重复/缺失事件任务中尝试调用禁止的写工具，宿主核验拦截、未落盘，最后仍回答 UNKNOWN；按相同严格评分记违规，不能表述为 Full 写错文件。

字段直送组恢复调用为 5 次，只增加步骤的插件为 43 次。已声明需求的短原文在实际读取后直接进入发送视图，模型更少绕行 JSON 查询或整段分页；实际业务读取、写入和检查均保留。

本轮字段直送组有 30 次写入核验通过、拒绝 0 次，仍不能把该组成绩解释为发生了真实错误写入纠正。当前结果支持这些受控任务下的正确完成与加速，不能保证任意任务始终正确。

## 速度与成本

- 字段直送相对 context_transform：总 token 减少 23.8%，固定参考费用减少 9.8%，平均耗时为其 0.77 倍，P95 为其 0.68 倍。
- 在两组均成功完成的同一批 35 个任务条件中，相对 context_transform 的平均耗时为 0.79 倍，P95 为 0.74 倍；该子集是补充分析，原始全组失败与成本没有排除。
- 字段直送相对 full：总 token 减少 86.3%，固定参考费用减少 84.6%，平均耗时为其 0.79 倍，P95 为其 0.75 倍。
- 在两组均成功完成的同一批 33 个任务条件中，相对 full 的平均耗时为 0.78 倍，P95 为 0.75 倍；该子集是补充分析，原始全组失败与成本没有排除。

调用前设定速度目标为 P95 不超过 Full 的 1.15 倍。本轮观测为 0.750 倍，目标达到。完整任务全部通过目标达到。

直送字段从本轮实际读取按已声明的 selector 提取，不调用额外模型，不提供格式化后的目标答案。完整原文仍归档；重复或缺失状态也从实际来源判定。未知格式保留恢复入口，写入核验和实际检查继续执行。

本轮全部 450 次真实请求计入，未知 usage 0 次，按固定命中/未命中参考价格合计 $0.283437，不是账单或实时价格。此前实验费用在同一账本中另列。没有自动重发或重跑至通过。

三次重复不能证明任意任务始终正确或始终更快。模板已用于调试；结果不覆盖任意自然语言、复杂开放任务或外部并发更新。服务商排队、网络和输出长度影响耗时，后续需冻结独立任务。
