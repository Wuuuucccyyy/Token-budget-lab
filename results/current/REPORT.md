## 本轮结论

原方案完整任务通过 4/12，精准定位通过 10/12；恢复调用分别为 42 和 16 次；context_stalled 分别为 5 和 0 次。每任务仍最多六次模型请求、三轮恢复，没有修改中间状态或删去失败。

Full 通过 11/12。精准定位与 Full 的逐任务答案一致率为 83.3%。总体通过率与逐题答案一致率分别评估，当前任务质量仍有差距。十二个情境是单次、包含重复模板的诊断，不能推断一般任务非劣性。

## 剩余问题与下一步

精准定位的两个失败均正确读取和定位了本轮来源：lookup-004 的 status_code=409 被写成 4.09，lookup-002 的 status_code=204 被写成 2.04。要求是保持数值大小并格式化为 409.00 和 204.00。检查通过但不能核验数值来源及变换，下一步应优先绑定原文字段并核验写入变换。

精准定位在新增六个边界情境全部通过，包括文本末尾目标；本轮没有恢复停滞或步骤耗尽。恢复调用明显减少，但 P95 比原方案略高，时延目标仍未达到，需要继续定位请求数及尾部耗时。

Full 的最终答案与文件状态均正确，其中一题重复事件先尝试 write_report(total=UNKNOWN)，handler 校验失败且未落盘，随后回答 UNKNOWN。按禁止写入请求的严格约束记为失败，因此完整任务为 11/12；答案准确率为 12/12。

全局历史检索仍可能混合多个版本，但本轮两个精准定位失败都使用正确的本轮来源，未观察到旧版本误选。相比立即改时序规则，本轮证据更支持先核验数值变换。

本轮没有实现自动时序来源筛选或本轮写入值核验。context_find 只按调用方指定的源定位；全局 context_search 仍保留不同版本，不能自动判定有效版本。

## 质量、成本与时间

- 精准定位相对 context_lexical：总 token 减少 19.9%，固定参考价格费用减少 18.3%，P95 为其 1.03 倍。
- 精准定位相对 full：总 token 减少 81.6%，固定参考价格费用减少 83.0%，P95 为其 1.23 倍。

三组共 172 次真实调用，未知 usage 0 次。固定参考价格合计约 $0.097676，不是账户账单或当前实时价格。全部恢复、失败与最终回答计入；没有额外缓存重放。

另保留 169 次协议诊断：条件题的执行合同提前提示写入分支，场景标签进入了文件 request_id。修正后所有条件题只声明同样的必需读取，条件写入由模型根据原文判断，场景 ID 改为无语义编号，并在评分阶段核对写后检查顺序。诊断质量不作为主成绩。两轮共 341 次调用，固定参考价格总估算约 $0.195604；没有删除前轮消耗。

两种插件的全部十二个情境均实际压缩，压缩子集成功率与各自全组相同。已有六个情境与六个新增边界情境分别统计，见 [case_groups.json](case_groups.json)。

## 协议与可核对资料

三组均使用同一执行合同、实际业务工具和评分条件。原方案通过 lexical 开关保持原两种恢复工具、原片段头部和归档入口；新方案增加 exact JSON lookup、完整小对象、字段路径及文本命中中心片段。旧前缀与工具定义在各组任务内固定，每个任务/组有独立首部标识；不能强制清空服务端缓存。

不读取答案或目标文件状态来定位证据。调用前冻结数据、配置和包源码；结果覆盖全部三十六个任务条件，执行凭据逐项核对实际 handler 日志。
