# DeepSeek 扩展实验报告（2026-10-09）

## 结论

在这套人工构造的合成样例上，BM25 句子检索把 56 个非重复问题的输入总量从 6,339 token 降到 4,495 token（减少 29.1%；每题平均约 113.2 → 80.3 token）；回答中包含预设正确片段的比例从完整上下文的 87.5% 降至 78.6%。这说明检索带来输入节省，但当前实现有质量损失，不能只用 token 节省率评价。

若连同精确重复问题的缓存一起计算，BM25 + exact 在全部 74 条请求上记录了 4,495 prompt token，相比 full + none 的 8,391 少 46.4%，API 调用从 74 次减至 56 次。这里包含 18 次完全重复问题的缓存收益；只看 56 条非重复问题，BM25 检索本身的输入节省是 29.1%。

## 数据与方法

- 请求：74 条，覆盖 20 份原创虚构校园材料、38 个事实标签。包含 18 条精确重复请求。
- 主统计样本：排除精确重复后 56 个问题；18 条重复仍计入系统级缓存/token 总量，但不作为独立准确率样本。
- API：DeepSeek `deepseek-flash`，Anthropic Messages 兼容协议，最大输出 256 token，默认思考模式；上下文预算按字符保留比例设为 50%，实际输入 token 以服务端 usage 为准。
- 每题质量指标：回答是否含有数据中预先指定的答案片段。它是自动粗筛，无法充分识别否定、歧义、事实完整性或正确引用。
- 区间：以材料为簇，对 20 份材料有放回抽样 20,000 次，计算宏平均通过率的 percentile 95% 区间。差值区间为同一轮材料抽样下，相对 full + none 的配对差。固定随机种子 20261009。

## 解读

- BM25 + none 节省 29.1% 的输入 token；唯一问题的片段通过率为 78.6%，比 full + none 低 8.9 个百分点。按材料配对 bootstrap 的差值区间为 [-26.7, 0.0] 个百分点，样本不足以支持“普遍变差”或“无损压缩”的强结论。
- BM25 + exact 对非重复问题的结果为 75.0%；但其系统级 API 调用更少，因为精确重复会直接复用答案。缓存和检索的收益应分别报告。
- Head truncation 尽管减少 30.0% 输入，却只通过 35.7%，说明简单截断容易丢掉位于材料后部的证据。
- 完整上下文本身只有 87.5% 片段通过率；空答、截断和模型本身错误都可能导致失败，因此不应把全部差异归因于压缩器。

## 局限与可复现性

这些材料是为实验人工构造的，问题和重复模式不是自然分布样本。20 个材料簇的 bootstrap 区间只能描述本数据设计下的波动，不能代表真实校园问答或其他任务的总体置信区间。片段包含指标也需要人工盲评和更强的语义判定补充。DeepSeek 输出有随机性，当前不是多随机种子重复实验。

实验记录包含 334 次有 usage 的调用；首次运行中有一条成功 HTTP 响应没有捕获 final 文本和 usage，随后重试一次，因此真实账单可能还包含这次未计量请求。该请求没有被记作零 token。公开的逐题 CSV 只保留 token 数、策略和评分字段，不发布生成回答全文或 API 凭证。

可复核文件：`deepseek_analysis.json`（统计摘要）、`deepseek_per_request_unique.csv`（逐题非重复样本，不含回答原文）。完整原始回答日志仅保存在本机实验目录，不应提交到公开仓库。
